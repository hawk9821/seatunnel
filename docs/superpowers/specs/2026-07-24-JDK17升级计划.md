# JDK 17 升级计划

## 1. 背景与目标

### 1.1 当前状态

| 项目 | 当前配置 |
|------|----------|
| Java Version | 1.8 (`<java.version>1.8</java.version>`) |
| Maven Compiler Source/Target | 1.8 |
| Dockerfile | `seatunnelhub/openjdk:8u342` |
| 官方支持状态 | JDK8/JDK11 |
| 项目版本 | 3.0.0-SNAPSHOT |

### 1.2 CI 验证情况

当前 CI 已验证 **JDK 8 和 JDK 11 双版本支持**，所有测试 job 在 `[ '8', '11' ]` 矩阵下运行。

### 1.3 升级目标

| 目标 | 说明 |
|------|------|
| 完全迁移 | 放弃 JDK 8 支持，仅支持 JDK 11/17 |
| API 兼容 | seatunnel 3.x 保持 API 兼容，用户替换 jar 包即可升级 |
| 最小修改集 | 只改必须改的文件，不做建议性升级 |

---

## 2. 升级路径

### 2.1 路径选择

采用 **直接升级 (Big Bang)** 策略：`java.version` 直接从 `1.8` → `17`，通过 Git 分支隔离验证。

### 2.2 验证标准

| 阶段 | 标准 |
|------|------|
| 编译 | `mvn compile` 成功 |
| 单元测试 | `mvn test` 全部通过 |
| 集成测试 | 完整 CI 测试全部 job 通过 |

### 2.3 验证流程

```
[创建分支 dev-jdk17]
    │
    ▼
[修改 pom.xml java.version = 17]
    │
    ▼
[mvn compile - 是否编译成功？]
    │
    ├── 失败 → 根据错误信息修复 → 回到 mvn compile
    │
    ▼
[mvn test - UT 是否通过？]
    │
    ├── 失败 → 根据失败信息修复 → 回到 mvn test
    │
    ▼
[触发 CI 完整测试]
    │
    ├── 失败 → 根据 CI 日志修复 → 重新触发 CI
    │
    ▼
[✅ 全部通过 → 合并到 dev]
[❌ 大量失败 → 回退，分析阻断性问题]
```

## 3. 必须修改的文件（最小修改集）

### 3.1 全局配置

| 文件路径 | 修改内容 | 风险等级 |
|----------|----------|----------|
| `pom.xml` | `<java.version>1.8</java.version>` → `<java.version>17</java.version>` | 🔴 必须 |

### 3.2 Dockerfile

| 文件路径 | 修改内容 | 风险等级 |
|----------|----------|----------|
| `seatunnel-dist/src/main/docker/Dockerfile` | `FROM seatunnelhub/openjdk:8u342` → `FROM eclipse-temurin:17-jdk` | 🔴 必须 |

### 3.3 硬编码 source/target=8 的模块

以下模块在 pom.xml 中硬编码了 `maven.compiler.source/target = 8`，需同步修改为 `${java.version}`（即 17）：

| 模块路径 | 当前配置 | 修改方式 |
|----------|----------|----------|
| `seatunnel-formats/seatunnel-format-protobuf/pom.xml` | `source=8, target=8` | 改为 `${java.version}` |
| `seatunnel-e2e/seatunnel-connector-v2-e2e/connector-typesense-e2e/pom.xml` | `source=8, target=8` | 改为 `${java.version}` |
| `seatunnel-e2e/seatunnel-connector-v2-e2e/connector-tdengine-e2e/pom.xml` | `source=8, target=8` | 改为 `${java.version}` |
| `seatunnel-e2e/seatunnel-connector-v2-e2e/connector-cdc-tidb-e2e/pom.xml` | `source=8, target=8` | 改为 `${java.version}` |
| `seatunnel-e2e/seatunnel-connector-v2-e2e/connector-fluss-e2e/pom.xml` | `source=8, target=8` | 需确认是否存在 |

### 3.4 不需要修改的文件（暂不处理）

以下为建议性升级，**不包含在最小修改集中**：

- Guava 版本（当前 27.0-jre，建议 32+，但不阻断）
- 其他依赖版本升级
- `--add-opens` JVM 参数（根据 CI 测试结果决定是否添加）

## 4. 预期风险与应对

### 4.1 高风险点

| 风险 | 描述 | 应对措施 |
|------|------|----------|
| 强封装 (Strong Encapsulation) | JDK 9+ 对 `sun.misc.*` 等内部 API 强封装，可能导致 `setAccessible(true)` 失败 | 根据错误信息添加 `--add-opens` JVM 参数到 surefire/failsafe 插件配置 |
| 动态编译 | `DynamicCompileTransform` 模块使用 Groovy 运行时编译 | 验证 Groovy 4.0.16 在 JDK 17 下的兼容性 |

### 4.2 中风险点

| 风险 | 描述 | 应对措施 |
|------|------|----------|
| JAXB 移除 | JDK 8 内置 JAXB，JDK 9+ 已移除 | 确认项目是否通过 shade 包含 JAXB 依赖 |

### 4.3 低风险点

| 风险 | 描述 | 应对措施 |
|------|------|----------|
| 第三方依赖 | Guava、Log4j2、Jackson 等 | 当前版本均支持 JDK 17，无需修改 |

## 5. 升级步骤

### Step 1: 创建分支

```bash
git checkout -b dev-jdk17
```

### Step 2: 修改全局 java.version

文件: `pom.xml`

```xml
<!-- 修改前 -->
<java.version>1.8</java.version>

<!-- 修改后 -->
<java.version>17</java.version>
```

### Step 3: 修改 Dockerfile

文件: `seatunnel-dist/src/main/docker/Dockerfile`

```dockerfile
# 修改前
FROM seatunnelhub/openjdk:8u342 as builder

# 修改后
FROM eclipse-temurin:17-jdk as builder
```

以及:

```dockerfile
# 修改前
FROM seatunnelhub/openjdk:8u342

# 修改后
FROM eclipse-temurin:17-jdk
```

### Step 4: 修改硬编码 source/target 的模块

对每个硬编码 `source=8 target=8` 的模块，修改为使用 `${java.version}` 变量：

```xml
<!-- 修改前 -->
<maven.compiler.source>8</maven.compiler.source>
<maven.compiler.target>8</maven.compiler.target>

<!-- 修改后 -->
<maven.compiler.source>${java.version}</maven.compiler.source>
<maven.compiler.target>${java.version}</maven.compiler.target>
```

### Step 5: 本地编译验证

```bash
mvn clean compile -DskipTests
```

### Step 6: 本地单元测试验证

```bash
mvn test -DskipIT=true
```

### Step 7: 提交并触发 CI

```bash
git add .
git commit -m "[Feature][Core] Upgrade Java version from 1.8 to 17"
git push origin dev-jdk17
```

### Step 8: 观察 CI 结果

| 结果 | 下一步 |
|------|--------|
| ✅ 全部 job 通过 | 创建 PR 合并到 dev |
| ⚠️ 部分失败 | 根据日志定位问题，修复后重新触发 |
| ❌ 大量失败 | 回退到 dev-jdk17 分支，分析阻断性问题 |

---

## 6. 回退方案

如果 JDK 17 升级存在根本性不兼容问题无法短期解决：

```bash
# 保留 dev-jdk17 分支作为后续工作区
# 在 dev 分支保持 java.version = 1.8

git checkout dev
git branch -d dev-jdk17  # 或 git push origin --delete dev-jdk17
```
